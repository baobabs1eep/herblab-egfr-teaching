# 中药单体筛选研学助手

面向中西医结合基础概论学习的证据研读与候选比较工具。首页默认以三叉神经痛作为开放研学主题，通过文献检索、化学线索提取、身份查询和人工确认，形成可讨论的验证方案与学习报告。肺癌 EGFR 保留为可选的三候选双排序教学案例。

本仓库同时用于团队协作和作品材料整理。**它包含教学原型及复核记录，尚不是经过实验验证的自动药物发现系统。**

建议体验顺序：**用户需求输入 → 文献检索 → 候选身份核对 → 人工确认 → 验证方案 → 结果回填与报告**。候选页可逐条核对，或依次查询前三条线索；PubChem、COCONUT、ChEMBL 的匹配记录需要用户明确选择，再确认身份与研究相关性并填写依据。数据库失败会保留错误状态。确认后的候选及来源、查询时间和确认记录会进入草稿与导出报告。新疾病缺少同协议计算、热度和过滤数据时不产生正式双排序；EGFR 示例可另行打开。

## 当前实现了什么

| 模块 | 当前状态 |
|---|---|
| 候选与文献展示 | 三候选身份、PubChem CID、样例 PMID 和证据语境 |
| 五阶段交互 | 左侧展示完整路径；需求、实验设计和结果回填在当前浏览器保存并进入导出报告 |
| 元器问答 | 已发布的单工作流：提问 → 知识检索 → 大模型回答 → 回复；网页内通过后端调用 |
| 常规／冷门双排序 | 同一候选队列上的确定性计算；支持参数调整、JSON 导入、名次变化与敏感性比较 |
| 计算复核 | 2ITW 同协议对接、共晶回对接、三个随机种子检查，以及原始日志和姿势文件 |
| 学习记录 | “我的研究”在当前浏览器保存最近 8 次检索，可重命名和继续查看；按疾病与候选隔离草稿；支持研究记录 JSON、纯文本、结构化 Word 兼容文档及浏览器打印/保存 PDF；不跨设备自动同步 |
| 公网演示 | HTTPS、免登录访问、后端密钥隔离、提问限流及证书续期配置 |
| 实时研究检索 | PubMed / Europe PMC 备用检索、化学线索待核验、用户触发的 PubChem 与 COCONUT 名称查询；新疾病不生成排名 |

尚未实现：完整多 Agent 自动执行、候选库扩容、第二教学案例、完整 ADMET／毒性评价、自动实验验证、教师账户与集中学习分析。实时检索只提供有限题录、摘要片段和待核验化学线索；网页提问通过服务端研究 ID 最多传入 3 篇摘要片段（每篇 350 字符），原生元器没有自动搜索工具。元器知识库问答**不会自动读取浏览器新导入的排序数据**。实验结果回填仅记录用户输入，不能替代实验核验。

本轮便捷功能及仍未完成的原规划见[补齐记录](会前准备/本轮便捷功能补齐_2026-10-05.md)和[原规划核对](会前准备/原始规划与实现核对_2026-10-05.md)。

| [`公网部署/`](公网部署/) | 现有 Nginx + systemd 部署配置、IP 证书续期配置和部署记录；没有账号密码或证书私钥 |
| [`docs/`](docs/) | 比赛提交、可见性和匿名性检查说明 |
| `Dockerfile`、`compose.yaml`、`Caddyfile` | 可选的 Docker + Caddy 部署方案 |
| `启动研学助手.cmd` | Windows 本地启动入口 |
| 根目录原始规划文档 | 团队早期方案和讨论资料；描述的是规划，不能据此认定功能已经实现，提交公开版前需匿名审查 |

历史阶段文件（名称含“待对接”“待补”“验证未通过”）用于保留过程，不作为当前正式数据。当前页面以 `三候选EGFR_2ITW教学双排序_已回对接.json` 为数据来源。

实时检索由 `本地服务/research.cjs` 和 `演示前端/research-ui.js` 提供，页面入口在“研究需求”阶段。PubMed 上游受限时服务端可使用 Europe PMC 官方 REST 备用；PubTator3 / PubChem 代码接入不代表云端每次都能通过 NCBI 上游限制。HERB、TCMSP 没有核实公开 API，也未全库导入。详见[数据库来源与当前覆盖范围](会前准备/数据库来源与当前覆盖范围.md)和[数据库接入说明](会前准备/数据库接入说明.md)。

## 数据、排序与适用边界

2026-10-09 新增 UniProt 靶点、ChEMBL 化合物与实验活性、Europe PMC PMID 核对查询及网页入口；新增 TCMSP/HERB 标准 JSON 导入工具。尚未导入这两个来源的真实全库数据，新代码尚需部署到公网。接口和核验记录见[本轮接入说明](会前准备/数据库接入补齐_2026-10-09.md)。

2ITW 的共晶配体 ITQ 首位姿势回对接 RMSD 为 **0.913 Å**，通过预设的 <2 Å 检查。三候选采用相同协议，三个随机种子的 Vina 分数次序一致。来源、参数和局限见[复现说明](会前准备/对接复现/README.md)，文献热度和基础性质来源见[核验记录](会前准备/文献热度与ADME核验_2026-09-26.md)。

页面初始参数为强／弱锚点 −12／−4、基础分门槛 **45**、冷门加分上限 **10**，用于观察三候选共同队列：常规次序为槲皮素、木犀草素、黄芩素；冷门次序为槲皮素、黄芩素、木犀草素。计算引擎原默认门槛为 50，该门槛下仅槲皮素入队。

这些参数未经科学校准。软件对接分数不等于实测亲和力或疗效，低文献热度不等于科学创新；已执行的两项基础性质预筛不等于完整 ADMET 或安全性评价。PAINS、CYP 等预测警示保留在原始记录中。

## 本地运行

需要支持内置 `fetch` 的 Node.js（建议使用仍受支持的 LTS 版本）；网页和后端没有额外 npm 安装步骤。

1. 克隆仓库，进入项目目录。私密仓库需要先接受协作者邀请。
2. 将 `本地服务/.env.example` 复制为同目录的 `.env`。只看页面和双排序可保留占位符；使用问答时，填入获授权的元器应用 ID 和 API 密钥。
3. 在项目根目录运行：

   ```sh
   node 本地服务/server.cjs
   ```

4. 浏览器打开 <http://127.0.0.1:8787/>。Windows 也可双击 `启动研学助手.cmd`。以前导入过旧排序记录时，点击“恢复当前三条核验资料”加载页面默认数据。

`.env`、演示密码和证书私钥不提交 Git。`127.0.0.1` 只指向自己的电脑；分享它不能让评委访问你的本地服务。

## 验证与复算

运行规则和服务测试：

```sh
node --test 本地服务/ranking.test.cjs 本地服务/public-server.test.cjs 本地服务/research.test.cjs
```

在双排序页“导出计算记录”后，可用同一组输入与参数复算：

```sh
node 本地服务/rank.cjs 双排序计算记录.json 复算结果.json
```

输出文件须使用尚不存在的文件名。直接传入不含参数的原始候选 JSON 时，命令行使用引擎默认门槛 50，可能与页面教学门槛 45 的结果不同；比较结果时必须同时核对参数。

## 部署与协作

现有服务器采用 Nginx + systemd，配置和验证记录见[公网部署说明](公网部署/README.md)。另提供 Docker + Caddy 方案：复制 `deploy.env.example` 为 `deploy.env`，填入自有域名、匹配的 `PUBLIC_ORIGIN`、独立演示密码及元器密钥，再运行 `docker compose --env-file deploy.env up --build -d`；Node 容器不直接发布公网端口。

队友先阅读 [CONTRIBUTING.md](CONTRIBUTING.md)，使用分支和 Pull Request 讨论修改。提交到 GitHub 不会自动更新公网演示站。评审提交应固定一个版本，并在提交系统中提供演示链接及备用录屏。
