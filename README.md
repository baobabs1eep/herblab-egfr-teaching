# 中药单体筛选研学助手 · EGFR 教学案例

面向药学学习的证据研读与候选比较工具。以槲皮素、木犀草素、黄芩素三种中药单体为例，让学生查看文献来源、比较同协议对接数据、观察常规／冷门排序如何随参数变化，并写下自己的判断和待核验问题。

本仓库同时用于团队协作和作品材料整理。**它包含教学原型及复核记录，尚不是经过实验验证的自动药物发现系统。**

## 当前实现了什么

| 模块 | 当前状态 |
|---|---|
| 候选与文献展示 | 三候选身份、PubChem CID、样例 PMID 和证据语境 |

## 数据、排序与适用边界

2ITW 的共晶配体 ITQ 首位姿势回对接 RMSD 为 **0.913 Å**，通过预设的 <2 Å 检查。三候选采用相同协议，三个随机种子的 Vina 分数次序一致。来源、参数和局限见[复现说明](会前准备/对接复现/README.md)，文献热度和基础性质来源见[核验记录](会前准备/文献热度与ADME核验_2026-09-26.md)。

页面初始参数为强／弱锚点 −12／−4、基础分门槛 **45**、冷门加分上限 **10**，用于观察三候选共同队列：常规次序为槲皮素、木犀草素、黄芩素；冷门次序为槲皮素、黄芩素、木犀草素。计算引擎原默认门槛为 50，该门槛下仅槲皮素入队。

这些参数未经科学校准。软件对接分数不等于实测亲和力或疗效，低文献热度不等于科学创新；已执行的两项基础性质预筛不等于完整 ADMET 或安全性评价。PAINS、CYP 等预测警示保留在原始记录中。

## 本地运行

需要支持内置 `fetch` 的 Node.js（建议使用仍受支持的 LTS 版本）；网页和后端没有额外 npm 安装步骤。

1. 克隆仓库，进入项目目录。私密仓库需要先接受协作者邀请。
2. 将 `本地服务/.env.example` 复制为同目录的 `.env`。只看页面和双排序可保留占位符；使用问答时，填入获授权的元器应用 ID 和 API 密钥。
3. 在项目根目录运行：

   ```sh
   node 本地服务/server.cjs
   ```

4. 浏览器打开 <http://127.0.0.1:8787/>。Windows 也可双击 `启动研学助手.cmd`。以前导入过旧排序记录时，点击“恢复当前三条核验资料”加载页面默认数据。

`.env`、演示密码和证书私钥不提交 Git。`127.0.0.1` 只指向自己的电脑；分享它不能让评委访问你的本地服务。

## 验证与复算

运行规则和服务测试：

```sh
node --test 本地服务/ranking.test.cjs 本地服务/public-server.test.cjs
```

在双排序页“导出计算记录”后，可用同一组输入与参数复算：

```sh
node 本地服务/rank.cjs 双排序计算记录.json 复算结果.json
```

输出文件须使用尚不存在的文件名。直接传入不含参数的原始候选 JSON 时，命令行使用引擎默认门槛 50，可能与页面教学门槛 45 的结果不同；比较结果时必须同时核对参数。

## 部署与协作

现有服务器采用 Nginx + systemd，配置和验证记录见[公网部署说明](公网部署/README.md)。另提供 Docker + Caddy 方案：复制 `deploy.env.example` 为 `deploy.env`，填入自有域名、匹配的 `PUBLIC_ORIGIN`、独立演示密码及元器密钥，再运行 `docker compose --env-file deploy.env up --build -d`；Node 容器不直接发布公网端口。

队友先阅读 [CONTRIBUTING.md](CONTRIBUTING.md)，使用分支和 Pull Request 讨论修改。提交到 GitHub 不会自动更新公网演示站。评审提交应固定一个版本，并在提交系统中单独提供演示账号及备用录屏。
