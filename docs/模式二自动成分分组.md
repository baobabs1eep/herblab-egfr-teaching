# 模式二自动成分分组

## 目的

模式二不再要求用户手工输入候选。系统按模式一已有顺序逐个处理候选，跳过不适合作为药物单体种子的条目，直到形成 10 个非空分组或模式一候选全部用完。

模式一的候选生成、数量、排序和展示不因本功能而改变。

模式二保留两个并列入口：

- `自动生成十组`：使用下述 TCMBank 严格候选池和自动分组规则；
- `人工输入与计算`：保留原有成分名称、参考分子、指定靶点、JSON 成分池导入和结构计算功能。人工输入结果单独核验，不会写回或改变自动十组的候选集合。

## 种子候选排除规则

- 水、常用溶剂、缓冲液、无机盐、实验辅助物和未定义混合物；
- 无法在 TCMBank 或 PubChem 核验明确结构的名称；
- RDKit 解析失败的结构；
- 重原子少于 5、精确分子量低于 70，或不含碳骨架的过小分子。

被排除的候选及原因会在页面中保留，不会静默删除。TCMBank 模糊名称匹配不能作为种子身份；系统会拒绝首条模糊结果并尝试 PubChem 结构。

## 每组成员规则

每个分组以一个有效的模式一候选为种子，成员取以下两条路径的并集：

1. 结构路径：使用 RDKit Morgan Fingerprint（ECFP4），半径 2、2048 位，Tanimoto 相似度大于等于 0.40；结构候选来自 TCMBank 官方 `ingredient_all.xlsx` 派生索引。
2. 靶点路径：种子与候选共享至少一个 TCMBank 已记录靶点。采用宽松规则，不要求共享靶点必须是当前疾病相关靶点；若同时属于疾病相关靶点，则单独标注。

无论通过哪条路径进入，成员都必须同时满足以下基础条件：

- 存在 TCMBank 成分编号和可计算 SMILES；
- TCMBank 官方表中的 `TCM_name`、`TCM_name_en` 或 `TCM_name2` 至少一项非空，即存在至少一条明确中药关联；
- 通过水、常用溶剂、无机物、过小分子等基础排除规则。

因此，HERB 不再参与模式二自动候选生成。靶点反查返回的成分若不在上述严格 TCMBank 中药关联池内，也不会进入结果。

索引按 RDKit 规范化 SMILES 合并同结构记录。同一结构对应的多个 TCMBank 编号和中药关系会汇总到一个候选，不会因数据库中的关系展开行重复显示。同一成分可以出现在不同种子组中。每组没有业务数量上限，页面每次显示 50 条并可继续加载。页面同时展示主要 TCMBank 成分编号、同结构编号数量和最多四个关联中药名称。

## 索引更新

官方原始表不提交到仓库。更新时先下载 TCMBank 官方 `ingredient_all.xlsx`，再执行：

```powershell
python 工具\extract-tcmbank-structure-source.py ingredient_all.xlsx tcmbank-ingredients.ndjson
node 工具\build-tcmbank-ecfp-index.cjs tcmbank-ingredients.ndjson 本地服务\data\tcmbank-ecfp4.json.gz
```

生产服务只读取压缩后的派生索引，不在用户请求期间扫描 Excel。

## 靶点相关性标签

- `有报道`：TCMBank 的靶点反查接口返回该成分关系；
- `结构上可能相关`：成分通过 ECFP4 结构阈值进入，但当前结果没有直接靶点关系记录；
- `无报道（当前数据源未检到）`：仅说明当前接入的数据源没有返回记录，不证明关系不存在。

## 证据边界

- TCMBank 的 `ingredient/totargets` 与 `gene/toingredients` 来自不同方向的数据，结果可能不完全一致；页面保留实际进入路径。
- 中药关联只证明 TCMBank 记录了“成分—中药”关系，不证明该成分是药材中的主要有效成分或达到治疗浓度。
- 成分—靶点关系不代表结合亲和力、作用方向、疗效或因果关系。
- 结构相似只用于发现候选，不代表具有相同药理作用。
- 模式二结果仍需人工核对身份、原始来源和实验依据。
