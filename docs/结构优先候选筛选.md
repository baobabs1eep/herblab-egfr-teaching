# 结构优先候选筛选（2026-10-09）

本版本按老师反馈替代冷门／惊奇度加分。候选可以来自成分数据库，不要求先有疾病相关论文；文献数量、数据库命中数不进入匹配分。

## 网页操作

在「研究需求」或「候选与排序」打开独立成分池。可查询 COCONUT 名称记录，或导入获准使用的 TCMSP、HERB 等 JSON 成分文件。支持现有 `import-candidates.cjs` 输出的 `{provenance, records}`；每条至少需要名称，可附 CID、SMILES、药材和来源链接。上限 1000 条；选取 1–8 条组成一批计算。未进行全库下载，也不假定 COCONUT 记录均为中药成分。

老师指定参考分子及可选人类靶点 UniProt 编号。参考分子应有明确选择依据，不能仅因结构相似就推断适应症。系统从 PubChem 获取 CID、InChIKey、ConnectivitySMILES 和 881 位二维指纹，以指纹交集位数／并集位数计算 Tanimoto，相似度分为 100 × Tanimoto。不读取论文或文献计数。保留所有候选，查询失败保持待补。

若指定靶点，系统从 ChEMBL 按 UniProt 编号核对唯一人类单蛋白靶点，并按候选完整 InChIKey 核对化合物，再查询该靶点的 binding assay 记录。显示 Ki、Kd、IC50 等原始类型、值、关系符、单位、实验和文献出处；不把不同实验或 IC50 混成实测亲和力。最多 20 条，超出时明确截断。查询失败不能当作零记录或零亲和力，也不会阻断结构比较。

结构相似度排序与完整匹配排名分开。导出匹配待补模板后，结构子分已有实际计算值；靶点／通道、亲和力、风险过滤和人工身份确认保持待补。只有补齐同目标、同规则、有来源的计算及过滤记录，才生成综合匹配排名。等权默认值属于教学草案，须在 metadata.matchWeights 明确记录评分方法与权重。

## 已实现与边界

已实现独立成分池、真实二维指纹比较、指定靶点的数据库结合记录核对、缺失数据保留、可复算导出，以及不使用文献热度的匹配引擎。

尚未实现全库自动发现适应症、未知靶点预测、所有单体自动对接／DTI、统一亲和力预测和实验验证。没有 ChEMBL 记录的分子仍可进行结构比较，但其亲和力不能因此推断。文献路径继续用于补充证据和课堂研读，不承担候选进入成分池的门槛。

公开数据库仍可能限流或不可达；后端逐条处理、缓存和超时，保留公网限流。导入文件及页面结果保存在当前浏览器，计算请求只提交本批名称、参考分子与指定靶点，不发送整个导入库。
