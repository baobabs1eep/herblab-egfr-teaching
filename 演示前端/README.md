# 肺癌 EGFR 候选比较教学演示

## 启动

双击项目根目录的 `启动研学助手.cmd`，保留服务窗口，然后在浏览器打开 http://127.0.0.1:8787 。网页里的聊天框会通过本地服务调用已发布的腾讯元器工作流，无需跳转。关闭服务窗口后，AI 问答停止；再次运行启动文件即可恢复。

不要继续使用 `file:///.../index.html` 进行 AI 问答。该方式只适合离线资料展示。HTTP 地址与旧 file 地址的浏览器草稿分开存储，旧草稿仍保留在原地址。

密钥位于 `../本地服务/.env`，仅由本地服务读取。修改密钥后重启服务。服务器只监听本机地址，只提供明确列出的前端文件，不公开密钥或配置目录。本版本用于本机演示，尚未部署公网服务。

## 已有能力

四步页面：教学任务、候选对比、证据研读、学习报告。展示三条候选及 PMID，保留学生笔记，导出 TXT 报告；聊天框调用腾讯元器的知识检索和大模型问答。回答为 AI 生成，需结合原文核验。资料来自 `../会前准备/肺癌EGFR教学候选_首批核验.csv`；更新 CSV 后需同步 `app.js` 中的候选字段。

## 演示顺序

查看三条候选 → 提问“黄芩素对应 PMID 是什么，能证明直接作用 EGFR 吗” → 查看真实回复 → 追问“可以按对接分数排名吗” → 记录证据与个人判断 → 导出报告。

目前缺少完整文献热度、同条件对接及 ADMET 数据，因此没有实现常规／冷门双排序。教师账户、自动实验验证、AI 回答自动纳入学习报告均尚未实现。

## 技术

本地 Node.js 服务使用官方元器 API（非流式），会把最近三轮完整问答作为上下文传入工作流的本轮问题，支持连续追问。应用 ID 从 `.env` 读取。应用只代理固定元器接口，不接受客户端提供密钥或上游地址。每次回答最多等待 90 秒，错误不会伪造为模型回答。

官方文档：https://yuanqi.tencent.com/guide/publish-agent-api-documentation


## 双排序（2026-09-26）

访问 http://127.0.0.1:8787/#ranking 。新页面支持真实数据缺口检查、JSON 导入、参数调整、常规/冷门排名、名次变化、加分敏感性比较和完整计算记录导出。排序摘要也会写进学习报告。原有元器聊天保留。

- `ranking.js`：浏览器与 Node 共用的纯计算引擎，规则版本 `herblab-ranking-0.1.0`。
- `ranking-data.js`：原始三条真实候选；未知数据均为空，不内置模拟名次。
- `ranking-ui.js` / `ranking.css`：双排序页面与样式。
- `../会前准备/双排序待补数据.json`：可以填写后直接导入的模板。
- `../会前准备/双排序数据准备说明.md`：字段含义、来源要求和待补工作。

导入数据保存在当前浏览器中，恢复原始资料前可导出备份。页面只检查字段和协议一致性，不会验证文件背后的科学真实性。过滤状态须依据真实执行记录填写，不能为了产生排名改成 pass。导入数据不会自动加入元器知识库，聊天中的回答仍需与程序结果分别核对。

网页导出的计算记录包含所有输入和参数，可用 `node 本地服务/rank.cjs 输入.json 结果.json` 从项目根目录复算。命令不会覆盖已有结果文件；另选文件名即可。`node --test 本地服务/ranking.test.cjs` 运行规则测试，夹具均为合成数据。

当前交付的是原方案双排序环节的可运行实现。默认公式与阈值为工程草案，尚未作科学校准；当前三条真实资料仍缺统一对接、ADMET/硬过滤和文献热度数据，不能产生正式排名。完整多 Agent 执行、候选库扩容、第二案例、实验反馈和公网部署仍未由本次改动完成。
