# 启真问智网站修改汇总

> 汇总日期：2026-10-10
>
> 项目定位：面向科研教学场景的中药单体研学助手
> 当前状态：本地修改和测试已完成，尚未提交、推送到 GitHub，也尚未部署到公网

## 1. 本轮修改目标

本轮修改主要解决以下问题：

1. 研究入口仍混入固定肺癌 EGFR 案例，不像通用疾病研究工具。
2. 用户输入其他疾病时，页面仍可能展示固定案例内容。
3. 文献数量少于数据库实际命中数，原“继续显示”并未真正请求下一页。
4. PubMed 在部分网络环境下容易连接失败或超时。
5. “候选与排序”没有清楚区分文献证据路线和脱离文献热度的结构机制路线。
6. ADMET、BBB、毒性等缺失数据没有统一、直观的展示方式。

## 2. 通用疾病研究入口

### 2.1 删除固定肺癌内容

- 研究需求输入页不再显示肺癌 EGFR 固定案例入口。
- 通用研究流程不再加载肺癌、EGFR、槲皮素等固定示例数据。
- 历史肺癌 EGFR 数据仍保留在仓库中，用于资料核对，但不在当前通用网页中展示。
- “独立成分候选池”已从研究需求输入页删除，避免用户尚未开始研究就看到另一套复杂功能。

### 2.2 首屏聚焦

当前首屏只突出“输入疾病并开始研究”这一核心任务，包括：

- 中文或英文疾病名称；
- 原发性高血压、三叉神经痛、类风湿关节炎快捷示例；
- 开始研究按钮；
- 折叠的高级条件；
- 离线研究资料导入入口。

### 2.3 高级检索条件

高级条件目前支持：

- 疾病全部文献；
- 中药与天然产物相关文献；
- 最新发表优先；
- 数据库相关性优先；
- 起始年份和结束年份；
- 可选靶点；
- 可选英文化合物名称。

年份输入会进行格式和先后顺序检查，避免把无效条件发送给数据库。

## 3. 文献检索修改

### 3.1 数据来源

当前检索链路为：

```text
用户疾病名称
  → 中文疾病名称规范化
  → PubMed 检索
  → PubMed 不可用时切换 Europe PMC 的 PubMed 记录
  → 返回题录和摘要片段
  → 提取待核验化学实体
```

页面会保留以下信息：

- 实际检索来源；
- 实际英文查询式；
- 获取时间；
- 数据库总命中数；
- 已实际获取的记录数；
- 上游切换和数据缺失警告。

### 3.2 真实数据库分页

原来的“继续显示”只是在浏览器中展开已经下载的记录，并不会继续访问数据库。

现在修改为：

1. 首次从数据库获取最多 20 篇；
2. 命中数更多时显示“从数据库加载更多文献”；
3. 点击后向 PubMed 或 Europe PMC 请求下一页；
4. 后续结果合并到同一个 `researchId` 研究会话；
5. 按 PMID 自动去重；
6. 页面同步更新已获取数量和是否仍有下一页；
7. AI 后续提问使用更新后的同一轮研究资料。

PubMed 使用 `retstart` 进行分页；Europe PMC 使用页码进行分页。分页上限受到服务端保护，防止一次研究无限请求外部数据库。

### 3.3 年份与排序

- PubMed 可按发表日期或数据库相关性排序。
- PubMed 年份条件转换为发表日期范围。
- Europe PMC 使用对应日期范围查询。
- 未指定年份时不额外限制发表时间。

### 3.4 网络连接与备用来源

已经加入：

- 请求超时；
- 429、部分 5xx 和网络错误重试；
- PubMed 被限制、返回异常或连接失败时切换 Europe PMC；
- 明确提示“检索失败不代表没有相关研究”。

Europe PMC 是当前主要的 PubMed 记录备用入口。它能降低因 NCBI 访问限制导致完全无法检索的概率，但无法保证所有网络环境下始终可用。

## 4. 文献结果页体验

结果页现在包含：

- 本轮疾病研究概览；
- 总命中数和实际获取数；
- 证据类型提示；
- 待核验化学实体概览；
- 检索来源和查询式；
- 可折叠的文献题录与摘要；
- PMID、DOI 和原文入口；
- 研究笔记；
- 证据类型筛选；
- 继续从数据库加载下一页；
- 基于本轮资料的 AI 快捷提问。

证据类型仍是依据题名和摘要关键词给出的浏览提示，不替代人工证据分级。

## 5. 候选与排序双模式

候选页面已明确拆分为两条彼此独立的路线。

页面采用“模式一 / 模式二”标签切换，一次只显示一条路线，切换状态保存在当前浏览器，避免两套候选和工具同时堆叠造成误解。

### 5.1 模式一：证据与数据库匹配

适用于已经在疾病文献或化学实体索引中出现的候选。

当前展示：

- 候选名称；
- 关联 PMID 数量；
- 候选名称在题名中的直接提及数量；
- 细胞、动物或临床等实验性记录数量；
- 当前出现的证据类型；
- 分子身份核对状态；
- 来源文献和数据库核验入口；
- 用户对身份与疾病相关性的确认记录。
- PubChem、COCONUT、ChEMBL 等身份数据库的核对覆盖；
- 已返回的靶点记录数量和候选当前研究讨论资格。

当前顺序是“证据整理顺序”，主要用于帮助用户优先检查资料。它不是疗效分数，也不会把文献数量直接解释为药物优劣。

在团队尚未确定科学有效的统一权重前，不生成任意的综合评分。

### 5.2 模式二：结构与机制潜力

该模式不要求候选已经有对应疾病文献，避免因文献热度造成候选准入偏置。

当前可使用：

- 导入 TCMSP、HERB 或其他获准使用的成分 JSON；
- 从 COCONUT 按名称查询天然产物记录；
- 使用 PubChem 身份与二维指纹计算结构相似度；
- 指定人类 UniProt 靶点后查询 ChEMBL 实验活性记录；
- 导出结构与结合记录；
- 导出完整匹配待补模板。
- 在计算前直接查看成分池中的候选名称、来源、来源中药和机制性质字段完整度。

新增六维数据完整性表：

| 维度 | 当前处理方式 |
| --- | --- |
| 结构 | 有真实 PubChem 结构计算时展示相似度 |
| 靶点／通道 | 使用导入数据或待接入 |
| 亲和力／活性 | 有 ChEMBL 记录或导入值时展示 |
| ADMET | 使用导入数据；缺失时显示“待接入” |
| BBB | 使用导入数据；缺失时显示“待接入” |
| 毒性 | 使用导入数据；缺失时显示“待接入” |

任何缺失维度都不会自动补零或虚构预测结果。即使六个维度都有数据，也必须先统一指标方向、单位、量纲和评分规则，才能进入综合排序。

### 5.3 成分池数据格式

成分池 JSON 目前可以包含：

```json
{
  "candidateId": "C001",
  "name": "英文成分名称",
  "cid": null,
  "smiles": "",
  "sourceHerb": "",
  "target": "",
  "channel": "",
  "affinity": "",
  "admet": "",
  "bbb": "",
  "toxicity": "",
  "dimensionSource": "数据库名称、版本或来源链接"
}
```

`dimensionSource` 应记录数据库版本、访问日期或来源链接，便于团队和评委复核。

## 6. AI 问答链路

- 网页通过服务端调用腾讯元器，API 密钥不进入前端代码。
- 每次成功检索生成短期 `researchId`。
- 用户提问时，服务端从本轮研究中选择最多 3 篇相关题录和摘要片段传给元器。
- AI 被要求标明 PMID、区分线索和证据、说明局限，并避免编造未执行的检索和实验。
- 加载更多文献后，服务端同一个研究会话会保存合并后的记录。

注意：网页展示的全部文献不会一次性全部传给元器。AI 回答不能替代阅读原文，也不能作为诊疗、用药或实验结论。

## 9. 当前仍未完成的部分

1. TCMSP 和 HERB 的完整、合规、可追溯数据尚未导入。
2. 尚未建立适用于任意疾病的完整疾病—靶点网络。
3. 尚未接入统一的 ADMET、BBB 和毒性预测服务或授权数据集。
4. ChEMBL 实验数据存在实验类型、单位和条件差异，当前不能直接混合为单一亲和力分数。
5. 尚未确定模式二综合排名的指标方向、标准化方法和权重。
6. 当前结构相似度只能说明二维结构接近，不能证明相同靶点、相同作用方向或相同适应症。
7. 外部数据库仍可能因网络、限流或地区访问条件暂时不可用。
8. 浏览器研究历史不跨设备同步，不等同于正式用户账户系统。
9. 当前本地修改尚未提交、推送到 GitHub，也未更新公网网站。

## 10. 建议的下一步

### 优先级一：团队验收与同步

1. 在浏览器中分别测试三叉神经痛、原发性高血压、类风湿关节炎和至少两个新疾病。
2. 检查首次 20 篇和“加载更多”后的记录是否连续、去重。
3. 对至少 5 篇记录人工核对 PMID、年份、题名和摘要。
4. 检查模式一的证据数量是否与当前已获取文献一致。
5. 导入一份带六维字段的成分池 JSON，检查模式二缺失状态。
6. 验收后提交并推送 GitHub，再更新公网服务器。

### 优先级二：补充模式二真实数据

1. 确认允许使用的数据集和授权范围。
2. 统一化合物主键、名称、CID、SMILES 和 InChIKey。
3. 为每个维度制定字段、单位、方向和来源规范。
4. 明确缺失值政策，不用零值代替未知。
5. 由团队或导师确认评分方法后再实现综合排序。
