## 调用流程

离线准备：获取候选数据 → 统一名称和结构、去重、保留来源 → 存成本地候选库。

用户输入疾病需求 → 大模型解析需求 → 确认疾病和靶点 → 从候选库取出分子 → PubChem 补全分子信息 → 计算筛选或读取预计算结果 → PubMed 检索并获取文献 → 核验相关性与证据 → 按确定的规则输出常规和冷门排名 → 展示候选详情和报告。

这是第一版拟用的执行顺序，便于减少对无关候选的文献查询。原方案中的前置文献步骤可用于整理疾病背景；候选确定后仍需逐个检索证据。先用固定案例讨论和验证，再扩展其他疾病。

## 已经实际验证的两项

### PubChem 分子查询

- 请求：`GET https://pubchem.ncbi.nlm.nih.gov/rest/pug/compound/name/quercetin/property/MolecularFormula,MolecularWeight,InChIKey/JSON`
- 本次未使用账号或密钥，返回 HTTP 200。
- 返回 CID `5280343`、分子式 `C15H10O7`、分子量 `302.23`、InChIKey `REFJWTPEDVJJIY-UHFFFAOYSA-N`。
- 返回原文保存在同文件夹的 `pubchem_sample.json`。
- 官方要求请求速率不超过每秒 5 次；正式程序还需缓存和失败重试。

### PubMed 文献检索

- 请求：`GET https://eutils.ncbi.nlm.nih.gov/entrez/eutils/esearch.fcgi?db=pubmed&term=quercetin%20AND%20EGFR&retmode=json&retmax=3`
- 本次未使用账号或密钥，返回 HTTP 200，得到检索总数和 3 个 PMID。
- 返回原文保存在 `pubmed_sample.json`，完整请求和结果保存在 `接口验证记录.json`。
- 未获取摘要或全文，也未核验具体文献内容。搜索命中不等于支持该分子有效。
- 正式热度统计需要统一同义词、疾病范围、检索字段和日期；此次宽泛检索不能直接作为最终热度评分。
- 官方说明无 API key 时上限为每秒 3 次请求；高频需求再考虑申请 key。
