# 启真问智项目改进汇总

> 汇总日期：2026-10-05
>
> 项目定位：面向科研教学场景的中药单体研学助手
>
> 当前性质：可运行的教学与研究辅助原型，不构成诊疗、用药或实验结论

## 一、改进目标

本轮改进围绕以下问题展开：

1. 原页面更接近固定肺癌 EGFR 演示，难以支持用户自由研究其他疾病。
2. 中文疾病依赖有限的内置别名表，未配置的疾病无法检索。
3. 前端同时展示通用检索、肺癌案例、排序、实验记录和 AI 对话，认知负担较高。
4. 文献检索结果偏原始，缺少研究概览、证据分型和清晰的下一步操作。
5. “用这些文献提问”只是填充输入框，没有形成连贯的研究流程。
6. 缺少研究历史、结构化报告和良好的移动端 AI 交互。

本轮最终形成两条明确分离的使用路径：

- **通用疾病研究**：用户输入任意中文或英文疾病，检索真实文献、查看待核验化学线索并向智能体提问。
- **肺癌 EGFR 教学案例**：保留三候选、样例论文、统一对接数据和双排序，用于展示完整教学流程。

## 三、腾讯元器与本地服务接入

### 3.1 API 配置

本地服务通过以下环境变量连接腾讯元器：

```env
PORT=8787
YUANQI_APP_ID=已发布元器的应用 ID
YUANQI_APP_KEY=replace-with-your-private-yuanqi-key
```

安全约束：

- `.env` 不提交到 GitHub。
- API 密钥只保存在服务端，不暴露到浏览器代码。
- 网页通过同源 `/api/chat` 调用本地服务，再由服务端请求腾讯元器。
- 公网模式要求 HTTPS、访问密码、Host 校验和跨域限制。

### 3.2 动态问答链路

当前问答不再是固定问题和固定答案：

1. 用户输入疾病并点击“开始研究”。
2. 服务端检索 PubMed；PubMed 不可用时切换 Europe PMC 的 PubMed 记录。
3. 服务端生成短期 `researchId`，保存本轮检索结果。
4. 网页提问时携带 `researchId`。
5. 服务端从本轮结果中选取最多 3 篇相关题录和摘要片段传给元器。
6. 元器依据本轮外部资料回答，并被要求标明 PMID、证据边界和不确定性。

实际验证过的疾病包括：

- 三叉神经痛
- 原发性高血压
- 类风湿关节炎

其中原发性高血压测试曾返回 67 条 PubMed 命中，并成功把文献传给元器生成带 PMID 的回答。

## 四、任意中文疾病名称支持

### 4.1 原问题

原服务只维护少量中文别名，例如“三叉神经痛”“肺癌”“糖尿病”等。输入“原发性高血压”时会在检索前被拒绝，并提示填写英文名称。

### 4.2 改进方案

现在采用两级规范化：

1. 常见中文疾病直接使用内置映射，减少额外调用和等待。
2. 未收录的中文疾病由已配置的元器转换为适合 PubMed 检索的英文医学术语。

同时增加以下保护：

- 限制输入长度和危险字符。
- 对元器返回的英文术语进行格式校验。
- 保留用户输入的中文名称和实际使用的英文检索词。
- 自动规范化失败时明确提示用户改用英文，而不是静默生成错误查询。

实际验证：

| 用户输入 | 实际英文检索词 | 结果 |
| --- | --- | --- |
| 原发性高血压 | `primary hypertension` | 检索成功 |
| 类风湿关节炎 | `Rheumatoid Arthritis` | AI 规范化后检索成功 |

## 五、真实数据与证据边界

当前已接入或保留的来源如下：

| 来源 | 当前用途 | 边界 |
| --- | --- | --- |
| PubMed | 疾病、靶点、化合物文献检索 | 命中不等于疗效或直接靶向证据 |
| Europe PMC | PubMed 不可用时的备用检索 | 与 PubMed 查询语法和命中数不可混用 |
| PubTator3 | 提取文献中的化学实体 | 机器提及可能是对照药、类别或溶剂 |
| PubChem | 按名称核对分子身份 | 名称查询不等于疾病相关性或疗效 |
| COCONUT | 核对天然产物名称与结构记录 | 名称相似不代表同一分子 |
| TCMSP | 外部人工核对入口 | 尚未完成授权数据导入 |
| HERB | 外部人工核对入口 | 尚未完成授权数据导入 |

新疾病检索只产生：

- 文献题录和摘要摘录；
- 机器提取的待核验化学实体；
- 可供讨论的研究线索。

新疾病不会自动获得：

- EGFR 教学案例的三候选；
- EGFR 2ITW 对接结果；
- 固定案例的文献热度；
- 缺少统一数据时的候选排名；
- 临床疗效或用药建议。

## 六、第一批前端体验改进

### 6.1 首屏聚焦

首屏从多模块混排改为单一核心任务：

> 你想研究什么疾病？

现在首屏主要包含：

- 疾病名称输入框；
- “开始研究”主按钮；
- 原发性高血压、三叉神经痛、类风湿关节炎三个快捷示例；
- 折叠的“高级条件”，其中包含可选靶点和英文化合物；
- 独立的肺癌 EGFR 教学案例入口。

首屏默认不显示 AI 对话栏，减少首次使用时的干扰。

### 6.2 通用研究与固定案例分离

- 通用研究只展示当前疾病的检索结果和化学线索。
- 肺癌 EGFR 被放入独立“教学案例”页面。
- 教学排序使用单独的 `case-ranking` 路径。
- 通用疾病进入“候选与排序”时只展示待核验线索，并明确说明数据不足时不排名。
- 固定槲皮素结构图和 PubChem 链接不再出现在通用助手区域。

### 6.3 检索过程反馈

检索期间显示以下阶段：

1. 识别并规范化疾病名称；
2. 连接 PubMed / Europe PMC；
3. 整理题录与摘要；
4. 提取待核验化学线索。

同时显示：

- 已等待秒数；
- 通常需要 10–30 秒的提示；
- 取消检索按钮；
- 超时、取消和上游失败的不同错误信息。

这些阶段是面向用户的处理状态提示，实际外部接口仍由单次服务请求完成。

### 6.4 结果页重构

结果页顶部新增“研究概览”，展示：

- 数据库总命中数；
- 当前页面展示的文献数；
- 根据题名和摘要初步提示的证据类型；
- 提取到的化学实体线索；
- 当前结果不能直接证明疗效、不能强行排名的边界。

文献改为折叠卡片，每张卡片显示：

- 英文原始题名；
- 期刊和日期；
- 初步证据类型；
- PMID；
- 展开后的摘要、DOI、PubMed 链接和研究笔记。

“人工核对”调整为更易理解的“加入研究笔记”。

### 6.5 一键 AI 提问

结果页提供三个快捷问题：

1. 总结文献的主要发现并逐条标注 PMID；
2. 提取可能涉及的天然产物或中药单体，并区分线索与已核验证据；
3. 分析证据类型、适用范围和主要局限。

点击后会：

- 自动把问题发送给 AI，而不只是填入输入框；
- 自动携带当前有效的 `researchId`；
- 在移动端自动打开 AI 助手抽屉；
- 在回答中把符合格式的 PMID 转换为可点击 PubMed 链接。

### 6.6 字号与视觉层级

- 正文、表单标签、输入框、AI 消息和辅助说明整体增大。
- 首屏主输入和主按钮得到更高视觉权重。
- 数据边界、来源信息和次要功能改为折叠或弱化显示。
- 一屏尽量只突出一个主要操作。

## 七、第二批功能改进

### 7.1 “我的研究”

当前浏览器会保存最近 8 次成功检索：

- 自动保存疾病、实际检索结果和时间；
- 支持重命名；
- 支持继续查看历史结果；
- 历史结果保存在浏览器 `localStorage` 中，不跨设备同步。

出于安全和有效期考虑，历史记录不长期保存可用的服务端 `researchId`。打开旧结果后可以阅读，但若要继续让 AI 使用这些文献，需要重新检索。

### 7.2 证据类型筛选

文献记录支持按以下类型筛选：

- 临床研究；
- 动物实验；
- 细胞实验；
- 计算预测；
- 综述；
- 待判定。

当前分类依据题名和摘要中的关键词自动提示，只用于快速浏览，不替代人工证据分级。

### 7.3 结构化报告导出

报告页现在支持：

- 结构化 Word 兼容文档 `.doc`；
- 浏览器打印或保存 PDF；
- 纯文本报告；
- 研究记录 JSON 导入和导出。

Word 报告包含：

1. 研究问题；
2. 当前讨论对象和证据状态；
3. 文献来源与 PMID；
4. 用户的证据判断和疑问；
5. 待审核验证方案；
6. 实际结果回填；
7. 科研教学和证据边界声明。

### 7.4 移动端 AI 助手

在宽度不超过 950 像素的设备上：

- AI 助手改为底部抽屉；
- 页面右下角显示“研习助手”浮动按钮；
- 点击快捷问题时抽屉自动打开；
- 抽屉提供关闭按钮；
- 首屏仍隐藏助手，保持输入疾病这一核心任务。

## 八、当前完整使用流程

```text
输入中文或英文疾病
  → 自动规范化疾病名称
  → 检索 PubMed / Europe PMC
  → 查看研究概览
  → 按证据类型浏览文献
  → 展开摘要并加入研究笔记
  → 查看待核验化学实体
  → 让 AI 基于本轮文献分析
  → 选择讨论对象
  → 记录验证方案与实际结果
  → 导出 Word / PDF / TXT / JSON 报告
```

肺癌 EGFR 教学案例使用独立流程：

```text
进入教学案例
  → 查看三候选资料
  → 核对三篇样例文献
  → 查看同协议教学双排序
  → 记录实验设计和报告
```

## 十一、当前仍存在的边界

1. 当前不是完整的多 Agent 自动药物发现平台。
2. 新疾病主要完成文献发现与线索整理，尚无自动靶点预测、批量虚拟筛选和统一排名数据。
3. TCMSP 与 HERB 尚未完成合规的数据导入。
4. PubChem、PubTator3 等上游接口可能受到网络访问限制。
5. 证据类型为关键词启发式分类，需要人工核对。
6. 英文文献题名尚未批量生成可靠的中文标题。
7. AI 每轮只接收最多 3 篇相关题录和摘要片段，不等于阅读了全部文献或全文。
8. 浏览器研究历史不会跨设备同步，也不等同于正式用户账户系统。
9. Word 导出为 Word 兼容 `.doc`，尚未生成原生 `.docx`。
10. 肺癌 EGFR 排序仍是教学数据，参数未作科学校准，不能作为疗效或临床推荐。
